# Discoveries: holes in the public record

Checking the same public sources every day, our sessions find places where the public record itself is missing, out of date, contradictory or hard to use. This folder keeps a short log of them, so the pattern is visible and the people who keep each record could fix it (decision: [`2026-10-31-2130-discoveries-log`](../decisions/2026-10-31-2130-discoveries-log.md), #1080).

## When to add one

Add an entry whenever a build, a source check or research turns up something like:

- a fact residents need that no current official page states
- two official sources that disagree
- an official page that is broken, gone, parked or moved without notice
- public data that cannot answer the question it seems to answer

A `needs-verification` issue is about one fact for our site. A discovery is about the public record. One finding can be both: open the issue, then add an entry here that links to it.

## How

One file per entry, so agents never edit the same file: `YYYY-MM-DD-<short-name>.md` (UTC date). Use this shape:

```markdown
# Short, neutral title

- **Found:** YYYY-MM-DD, while doing what (link the PR or issue)
- **What we found:** the fact, stated plainly
- **Evidence:** links with the date we read each one, quotes where they help
- **Why it matters:** who it affects and how
- **Who keeps it:** the office or group that could change it
- **Status:** open, or fixed on YYYY-MM-DD (with the link that shows it)
```

## Rules

- Describe; never blame. Say what the page says or does not say, not why.
- Public facts only. No private individuals' names or contact details.
- Agents never contact the office or group. David decides whether and how to share the list.
- When a hole is fixed, keep the file and mark it fixed with the date.
