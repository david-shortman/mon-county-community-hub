- **Why the numbers were wrong:** on SeeClickFix, a request moves from "closed" to "archived" 7 days after it is closed. The weekly run counted only "closed", so most finished requests were missing. The 2026-11-09 run said 18 closed and 753 archived. Its median of 0.7 days came from only those 18, and potholes had no median at all (0 closed, 219 archived).
- **Shipped:**
  - `site/src/lib/totals-311.mjs`, the counting rules:
    - "closed" is now closed plus archived, and "archived" is still shown on its own.
    - The median days to close uses both, from each request's closed date.
    - The median is `null`, with a `median_null_because` line, when fewer than 30 requests go in, or when any closed or archived request has no closed date. The API docs do not say whether archived requests keep their closed date, so the next run's output will show it.
  - `site/scripts/check-311.mjs` uses the new module, and its note explains the rules. The note still says closed does not always mean fixed.
  - `site/test/totals-311.test.mjs`: 5 tests.
  - The 311 workflow also re-runs when the new module changes, so a fresh run starts on its own when this merges.
