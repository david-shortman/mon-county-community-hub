# 2026-10-30: schema.org markup for listings and in-person events

- **Considered:** #37 asks for schema.org JSON-LD built from the YAML: `Organization` for orgs, `Service` or `GovernmentService` for resources, and `Event` only for in-person entries with a physical address, never for deadlines. The site has no page per record; listings show as cards on topic pages, and the card components belong to the presentation lane, with many open PRs touching them.
- **Chose:** add the markup without editing any component or layout. A new build-time middleware (`site/src/middleware.js`) reads each built page, finds its cards (`<article class="card resource|place|event" id="<slug>">`), looks up those records, and adds one JSON-LD block to the page head. Resources become `Service`, or `GovernmentService` when a government office runs them, with the organization as `provider` (`GovernmentOrganization`, `NGO`, `EducationalOrganization` or `Organization`). Calendar entries become `Event` only when they have a `place`; deadlines and application windows have none, so they get no markup. Timed events carry the Eastern offset for that day. Hidden records are not loaded, so they never get markup.
- **Shipped:** `site/src/lib/jsonld.mjs`, `site/src/middleware.js`, and `site/scripts/check-jsonld.mjs`, which runs after every build: each block parses, every Event has a name, a start date and a location with an address, and no em dashes. 19 pages, 56 items, 15 in-person events on this build. Also fixed the `check-api` npm script, which #614 had set to run the calendar test too.
- **Not done:** Google's Rich Results Test is a web tool that cannot run in CI here; the check covers Google's required Event fields instead. Pages that show listings in another layout (like the answer boxes on the utility bills page) get no markup yet.
- **Cost:** $0.
