# 2026-10-30: Door and topic tags, and a build that makes the lists (#249)

- **Considered:** every new page meant a hand edit to the menu, the footer and the home page list, and the menu already had eleven items. The site plan (#248) sorts pages into five doors named for what is going on in a person's life. This is its first step, and every later door issue builds on it.
- **Chose:** each page carries `export const page = { door, topic, label, summary }` in its own frontmatter, so two PRs adding pages never touch the same file. `content/doors.yaml` lists the five doors and three lanes (Help now, Dates, About this site) and maps every content topic to one door. Links stay short and flat, so renaming a door breaks nothing.
- **Shipped:** a Topics page (`/topics/`) with every door, its topics and pages, plus A to Z; breadcrumbs above the heading ("Home › Get through this month › Food help"); door and topic filters in the search index; an "All topics" link in the menu and footer; and a check that fails when a page tag or a content topic does not match a door. Doors with no pages yet say so and point to 211. A breadcrumb that would only say "Home" is left off, so urgent pages like Stay tonight keep their first screen.
- **Not yet:** the menu itself still lists pages by hand. #250 replaces it with the doors. Door pages come with #251 and #252; until then a door's breadcrumb links to its section of the Topics page.
- **Scoreboard:** no resident-facing change in findability yet. The Topics page gives every page a second path in, linked from the More menu and the footer on every page.
