# 2026-10-31: How this site works page

- **Considered:** David asked for a public page that shows curious residents how the whole thing fits together, and to learn from how Anthropic and public bodies present technical explainers. About, The idea, How we check and Hard questions already cover who checks what, the goals, the checking standard and tough questions, so this page shows the system as a whole and links to them instead of repeating them.
- **Chose:** a layered page, the way public explainers do it. A two sentence summary and a short version box first, with who to contact if something is wrong (the UK public research on algorithm transparency put contact details up front). One labeled picture of the path a listing takes, with a short walk-through (like Anthropic's engineering posts on its agent systems). Then who does what, how things are sorted and kept, the automatic checks, what it's for, and a candid list of limits. The picture is plain HTML and CSS, top to bottom, so it works on any phone, with any text size and with a screen reader.
- **Shipped:** `/how-it-works/` (About lane, listed on Topics on its own), and a link from About's Read more list. Every claim points to a file in the repo: workflows, `docs/COORDINATION.md`, `docs/CHARTER.md`, `content/doors.yaml`, `content/README.md`, `docs/operations/README.md`, the rubrics and the scoreboard. The one number (days to act on a group's request) comes from `REQUEST_DAYS`, so it stays true.
