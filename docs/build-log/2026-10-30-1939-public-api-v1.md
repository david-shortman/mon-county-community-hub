# 2026-10-30: Public data API v1 (static JSON on Pages)

- **Considered:** #72 asks for the data as static JSON next to the site, an OpenAPI description, `llms.txt` pointers, and a contract test (ADR 0003, still proposed). It depends on the shared data layer in #69, which would touch files every lane edits during the sprint, so the API reads through the existing loader in `site/src/lib/content.mjs` instead. When #69 lands, only `records()` in `site/src/lib/api.mjs` needs to change.
- **Chose:** one place, `TYPES` in `site/src/lib/api.mjs`, defines the v1 shape of each record type (orgs, resources, calendar, corrections). Records are trimmed to those fields (nothing internal like `_file` leaks), dates are always `YYYY-MM-DD`, and `sources` pass through as they are. The OpenAPI file is made from the same shape, so the two cannot drift.
- **Shipped:**
  - `/api/v1/index.json` (types, counts, license and credit line read from `content/LICENSE.md`, build time, canonical base URL, versioning rule), `/api/v1/<type>.json`, `/api/v1/<type>/<id>.json`, `/api/v1/openapi.yaml`.
  - Calendar records are the same set as `calendar.ics`: every entry that has not ended, hand-checked plus live-feed entries (with their `feed` object).
  - `scripts/check-api.mjs` runs after every build. It fails when a field in the saved shape (`src/lib/api-contract-v1.json`) is removed or renamed, with a message pointing to the versioning rule, when a new field is not written into the contract, or when a built file does not match the shape. Tried by renaming `website` to `web`: the check failed with "field website was removed or renamed".
  - A short `/data/` page (About lane) with what is published, the license, and how to cite. `llms.txt` gets a Data section.
- **Not done here:** the For groups and helpers page still lists JSON as "planned"; that page waits for David, so the update is a separate PR. HSDS export is #73; the MCP server is #75.
- **Cost:** $0. GitHub Pages already serves files with `access-control-allow-origin: *`.
