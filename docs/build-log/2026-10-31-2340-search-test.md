# Site search test and first fixes (#529, wave 6)

**What:** A repeatable test of the site's own search box. About 250 queries in residents' words ("food stamps", "shut off notice", "dentist cheap", "medicade", full questions), each with the page that should come back. `npm run search-test` in `site/` scores whether that page is in the top 3, and CI adds the report to every Site run without ever failing it. How it works: [`docs/operations/search-test.md`](../operations/search-test.md).

**Why:** The findability tests check how people find help with a web search. Nobody had checked our own search box. On the first run, misspellings found the right page 12% of the time, and repeated lists (printable sheets, Make a list, "Also check" links) often pushed the real guide out of the top 3.

**What changed in this PR:**

- `site/src/lib/search-plan.mjs`: the search steps the page will use, shared with the test: fix common misspellings, drop question words, and when no page has every word, show pages that match the most words.
- `content/also-called.yaml` and `AlsoCalled.astro`: a visible "Also called: ..." line at the end of a page, for plain words the page answers but never says (for example "garbage pickup" on Trash and recycling, "lawyer" on Courts and legal help). Pages about shelter, crisis, food or benefits are left for a separate PR that waits for David.
- Search skips the "Also check" links and the Make a list place list, so a page is found for its own words.

**Scores:** in the PR description and in `content/findability/search-runs/`. The search page itself switches to the new steps, with a more helpful "no results" message, in a follow-up PR that waits for David because the search page names 211.
