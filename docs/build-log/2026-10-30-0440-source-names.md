# 2026-10-30: Cards name who published each source, and buttons get short labels (#327, #335)

- **Considered:** resource cards showed a bare web address as the source ("va.gov/clarksburg-health-care"), and website buttons showed raw domains that broke mid-word on phones ("Open monongaliacountyswa.com"). Door pages already named the organization, but by assuming every source belonged to the record's org.
- **Chose:** one shared `SourceLine` component for every card's small print, and a `websiteLabel` helper for buttons.
- **Shipped:**
  - `site/src/components/SourceLine.astro`: "Source: Mon River Trails Conservancy: montrails.org/rail-trail-info. Checked October 29, 2026." Sources are grouped by publisher. A source is credited to an organization only when its address is on that organization's own site; otherwise it shows the address alone, so a page is never credited to the wrong group. Each link has a screen reader name that says which card it belongs to.
  - The checked date is now the oldest across a card's sources (it was the newest on some cards), so we never overstate how fresh an item is (#39).
  - Used on resource cards, place cards, answer page facts, door steps, the "can't wait" strip, and Scott's Run on the food page. Calendar cards name the publisher too.
  - Buttons (#335, following David's update on the issue): a short label that says what the person gets, never a raw web address. "Website" by default, "More details" on calendar cards, and a purpose label where a record's link is plainly for one thing (`contact.url_label`, such as "Apply online", "Trail info", "Office locations"). Buttons stay compact in the existing two-column grid, and Call stays the one full-width action. The domain still shows once, in the source line.
- **Scoreboard:** Trust TR1 (sources named) and #335's "no button shows a raw URL" (checked across every built page).
