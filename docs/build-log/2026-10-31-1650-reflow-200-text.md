# 2026-10-31: No sideways scroll at 200% text (#971)

- **Considered:** with text at 200% on a 320px screen, 21 pages scrolled sideways: all 19 community center flyers, Compare halls, and How is Mon County doing? People who make text bigger then have to scroll left and right on every line (WCAG 1.4.4 and 1.4.10).
- **Found:** three causes. The flyer QR code box is 9rem wide and never shrinks. On phones, the Compare halls table shows rows as cards, but the table box itself still grew to fit its caption and cells. On How is Mon County doing?, the "See every number" tables and the number tiles (at least 14rem each) were wider than the screen.
- **Chose:** fix shared parts first. The trend chart component now puts its number table in the site's existing sideways-scroll box, which fixes those tables on every page that uses the chart. The halls card view is now a plain block, with `role="table"` and a label so screen readers still hear a table. `npm run check-a11y` now also checks every page at 320px with text at 200%, so this cannot come back unnoticed.
- **Left for David's PRs:** the flyer page and the How is Mon County doing? page each have an open `for:david` PR (#938 and #956), so this PR does not edit them. The two one-line fixes are posted on those PRs. Until they merge, the check prints a note for those 20 pages instead of failing.
- **Checked:** 130 pages at 320px with text at 100% and 200%, 390px at 200%, and 1280px at 200% and 400%. 400% text squeezed into a 320px screen still overflows on every page, which WCAG does not ask for (400% zoom on a 1280px screen equals the 320px check, and that passes).
