# 2026-10-30: A read-only MCP server over the open data

- **Considered:** #75 asks for a small MCP server in `apps/mcp/` that reads the static API from #72, runs over stdio from a clone, and costs nothing to host. The official MCP SDK would add a dependency tree and a second lockfile; the stdio protocol for a read-only tools server is small (initialize, tools/list, tools/call, ping), so the server is one file with no dependencies.
- **Chose:** five tools: `search_services`, `get_organization`, `upcoming_dates`, `list_needs`, `how_to_report_a_problem`. Each result carries the record's `sources`, its oldest and newest checked dates, and `stale: true` with a note when a source is over 6 months old (the site's rule: a record is as old as its oldest source). Tool descriptions say the data comes from public sources to check before acting, and that the server describes programs and never decides who qualifies. No free-text answers: it returns records only, and points to 211 when nothing matches (design rules from the peer landscape on #75).
- **Shipped:** `apps/mcp/server.mjs`, `apps/mcp/README.md` (setup for Claude Code and JSON-config clients, plus hosting options and what each would cost; hosting is David's call), and `apps/mcp/test/smoke.mjs`, which the site build now runs against `dist/api/v1`. Also run against the live API, which answers with `access-control-allow-origin: *`.
- **Example:** asked `search_services` for "help paying heating bill", the server returned LIEAP from the WV Department of Human Services first, with phone 800-642-8589, the WV PATH link, and its two sources checked 2026-10-28, `stale: false`.
- **Not yet:** `list_needs` returns an empty list until the API publishes `needs.json` and #44 adds entries.
- **Cost:** $0.
