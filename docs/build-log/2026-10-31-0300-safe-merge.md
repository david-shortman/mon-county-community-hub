# 2026-10-31: scripts/safe-merge.sh, so for:david PRs are not merged by mistake

- **Considered:** three PRs labeled `for:david` were merged today (#712, #787, #906). The High stakes check adds the label a minute or two after a PR opens or changes, and sessions merged with a raw `gh api ... /merge` before the label arrived or without reading it.
- **Chose:** a merge script that refuses (exit 4) when the PR has `for:david`, or when the High stakes run for the PR's current head commit has not finished green. It re-reads the labels just before merging, passes the head commit to GitHub so a last-second push is refused, then runs `scripts/pr-wait.sh main`.
- **Shipped:** `scripts/safe-merge.sh` and step 4 in `docs/operations/merge-conflicts.md`. Tested: it refuses #776 (`for:david`) and an already merged PR. This PR was merged with it.
- **For David:** the merge command in `CLAUDE.md`, `docs/COORDINATION.md` and the sprint instructions still says `gh api ... /merge`. A `for:david` issue asks to point them at the script, and to consider a branch rule (#95) so GitHub itself blocks the merge.
