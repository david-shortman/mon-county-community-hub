# 2026-11-01: Weekly scorecard, slow-phone speed and lag on high-stakes changes (#1052, #1053, #1056)

- **Considered:** David asked for a regular check of whether the site is better than what residents have today. Almost every number already existed, spread across the build, the findability files, the source benchmark, the Source check and Health issues, and the accessibility doc. Two things were not measured at all: load speed on a slow phone, and how long a known change to a high-stakes page takes to go live. On October 31 the heating bill page kept last season's "dates not out yet" line after its record was fixed, because the line was typed into the page (#1056).
- **Chose:** one script that gathers what exists, plus a free Lighthouse run in GitHub Actions instead of Google's PageSpeed tool (its shared daily limit runs out, and a key would be an outside account). Cost: $0, about 10 minutes of a free GitHub runner a week.
- **Shipped:**
  - `site/scripts/scorecard.mjs`: writes `docs/scorecard/YYYY-Www.md` and `.json`, one table per lane (information, presentation, infrastructure, outcomes) with today's sources, this week, last week and a Move column that ignores noise (findability moves of 2 or less). How it works: [`docs/scorecard/README.md`](../scorecard/README.md).
  - `site/scripts/lighthouse.mjs` (#1053): Lighthouse 13.5.0 mobile test (simulated slow 4G, CPU 4 times slower) on home, stay tonight, utility bills, get through this month and food help. Warn only. Goal: main content in under 2.5 seconds.
  - Lag on known changes (#1056): open PRs that change high-stakes files, by the same rules as the High stakes check, with age in days and a 2-day goal; and two typed-text hints on high-stakes pages from `check-typed-facts.mjs`: lines that say a date is "not out yet", and typed phone numbers that no record has.
  - `check-weight.mjs` now also writes `dist/page-weight.json`, like `check-reading.mjs` writes `dist/reading-grades.json`.
  - `.github/workflows/scorecard.yml`: Mondays at 10:23 UTC. Builds, runs Lighthouse, makes the scorecard, then opens and merges a PR that adds only the two scorecard files. If GitHub will not let it, it opens a `for:code` issue with both files.
  - The first scorecard, [`docs/scorecard/2026-W44.md`](../scorecard/2026-W44.md), made by hand on main. Next Monday's run compares against it.
- **First numbers:** all five key pages show their main content in about 1.0 to 1.2 seconds on slow 4G. 9 open PRs change high-stakes pages, none older than 2 days. 3 "not out yet" lines and 12 typed phone numbers with no record are listed for a person to re-check.
- **Limits:** "lag" counts changes that are written but not live; it cannot see a change in the world nobody has written up. The typed-text counts are hints, not errors. Visits are not measured; that waits on David.
