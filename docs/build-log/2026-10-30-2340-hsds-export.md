# 2026-10-30: Listings in Open Referral HSDS, the format 211 tools read

- **Considered:** #36 asked for a field-by-field map from `orgs/` and `resources/` to HSDS, and #73 for the export itself. Read the HSDS 3.1.1 schema files Open Referral publishes. They are under CC BY-SA 4.0, so they are not copied into the repo; the check fetches them at the pinned version.
- **Chose:** a direct map with nothing guessed. Hours stay free text (no schedule rules), cost stays text (no amounts), and `place` is not turned into an HSDS address, because HSDS needs a postal code our records do not have. Calendar entries and corrections have no HSDS object and stay in our own API. Ids are UUID v5 from our slugs, so they never change between builds. No 211 taxonomy codes or terms.
- **Shipped:**
  - `docs/architecture/hsds-mapping.md`: every field mapped or marked "no HSDS equivalent", the gaps, and fields we leave out for privacy (named contacts, `assurer_email`, `tax_id`, `metadata.updated_by`).
  - `/api/v1/hsds/organizations.json` and `services.json`, one file per record by UUID, and a Tabular Data Package: `organizations.csv`, `services.csv`, `phones.csv`, `schedules.csv` and `datapackage.json` naming CC BY 4.0.
  - `site/scripts/check-hsds.mjs` runs after every build: every record validates against the published HSDS 3.1.1 schema, ids match the RFC 4122 test value and a fixed namespace, and the CSV headers and row counts match the package and the JSON. If the schema cannot be fetched, that part is skipped with a warning.
  - Hidden listings (#519) are never exported, and a service whose org is hidden is left out, since HSDS needs its organization.
  - The `/data/` page, `llms.txt` and the API catalog (`exports`) link the export.
- **Cost:** $0.
